# RB-MLTT “RB-TT Fragment” Specification

**Status**: Draft for Checkpoint K3.2 (2026‑01‑15)\
**Purpose**: State the precise Lean bridge theorem relating RB-MLTT to the RB-TT fragment described in the paper (Proposition “RB-TT fragment”).

---

## 1. Fragment Description

The RB-TT fragment of RB-MLTT is obtained by restricting to:

- **Types**: Those generated by the STLC type grammar (Nat, Bool, products, arrows) with no dependency on term indices.
- **Terms**: STLC terms lifted into the RB-MLTT syntax via an erasure embedding `eraseTm`.
- **Bounds**: Bound language expressions that do not use `app`, `sum`, or index binders; i.e., they collapse to the simple additive/join expressions already present in RB-TT.

Formally, define a predicate `IsRBTTType : DepTy → Prop` inductively:

```
IsRBTTType (.Nat)            -- base types
IsRBTTType (.Bool)
IsRBTTType (.Prod A B)  if IsRBTTType A ∧ IsRBTTType B
IsRBTTType (.Arr A B)   if IsRBTTType A ∧ IsRBTTType B
```

Likewise `IsRBTTTm : DepTm Γ A → Prop` requires that every constructor used comes from the STLC subset and all type annotations satisfy `IsRBTTType`.

---

## 2. Erasure Functions

We define erasure from RB-MLTT to RB-TT in Lean as mutually recursive functions:

1. `eraseTy : {A : DepTy} → IsRBTTType A → Ty`
   - Maps each dependent type to the corresponding STLC type.
2. `eraseCtx : DepCtx → Prop × Ctx`
   - For a context `Γ` consisting only of `IsRBTTType` entries, returns the STLC context `Ctx`.
3. `eraseTm : {Γ : DepCtx} {A : DepTy} → IsRBTTCtx Γ → IsRBTTType A → DepTm Γ A → Tm (eraseCtx Γ) (eraseTy A)`
   - Removes dependent annotations and produces a plain STLC term.
4. `eraseBound : Bound → RBTT.Bound` (optional)
   - Collapses bound expressions by removing `app`/`sum` nodes (only applicable when the input satisfies the fragment predicate).

These functions will be defined only when the fragment predicates hold; otherwise they are undefined/inhabited by `False`.

## 3. Fragment Typing Judgments

Let `DepHasBound` be the RB-MLTT typing + bound judgment. For the fragment we prove:

```
theorem rbtt_fragment_sound {Γ t A b} :
  IsRBTTCtx Γ →
  IsRBTTType A →
  IsRBTTTm t →
  DepHasBound Γ R b t A →
  RBTT.STLC.HasBound (eraseCtx Γ) R (eraseBound b) (eraseTm t) (eraseTy A)
```

Conversely, we provide a lifting lemma:

```
theorem rbtt_fragment_complete {Γ t A b} :
  RBTT.STLC.HasBound Γ R b t A →
  DepHasBound (embedCtx Γ) R (embedBound b) (embedTm t) (embedTy A)
```

Where `embed*` functions inject RB-TT data back into RB-MLTT:
- `embedTy : Ty → DepTy` (trivial inclusion)
- `embedCtx : Ctx → DepCtx`
- `embedTm : Tm Γ A → DepTm (embedCtx Γ) (embedTy A)`
- `embedBound : RBTT.Bound → Bound`

## 4. Precise Lean Statement

We intend to codify the bridge theorem as:

```lean
namespace RBTT.RBMLTT

structure FragmentCtx (Γ : DepCtx) : Prop :=
  (entries_rbtt : …) -- every entry satisfies IsRBTTType

structure FragmentBound (b : Bound) : Prop :=
  (no_dep_constructs : …) -- b uses only zero/res/add/join/scale/termBound

theorem rbtt_fragment
    {Γ : DepCtx} {t : DepTm Γ A} {b : Bound} {R : ResCtx}
    (hΓ : FragmentCtx Γ) (hb : FragmentBound b) (ht : FragmentTm t) (hA : FragmentTy A)
    (h : DepHasBound Γ R b t A) :
    RBTT.Core.HasBound (eraseCtx hΓ) R (eraseBound hb) (eraseTm ht) (eraseTy hA)

theorem rbtt_fragment_backward
    {Γ : Ctx} {t : Tm Γ A} {b : RBTT.Bound} {R : ResCtx}
    (h : RBTT.Core.HasBound Γ R b t A) :
    DepHasBound (embedCtx Γ) R (embedBound b) (embedTm t) (embedTy A)
```

Here `FragmentTm` guarantees that `t` uses only STLC constructors and any bound applications are trivial; `FragmentTy` ensures `A` is in the RB-TT subset. The erasure functions are bundled with proofs that they erase contexts/types/terms/bounds consistently.

## 5. Proof Strategy Sketch

1. **Forward direction**:
   - Induct on the `DepHasBound` derivation. Each case reduces to the corresponding RB-TT rule because the fragment predicates prevent dependent-only constructors from appearing.
   - Use helper lemmas showing `eraseTm` preserves substitution and beta reduction (needed for application case).
2. **Backward direction**:
   - Straightforward: use `embed*` to lift STLC terms into the dependent syntax and reconstruct the DepHasBound derivation.
3. **Bound erasure**:
   - Prove that `eraseBound` commutes with addition/join/scale and that it is well-defined on the restricted syntax class.

These sketches will guide the actual Lean proof once the DepHasBound judgment and bound language are implemented.
